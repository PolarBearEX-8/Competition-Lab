# Daily coverage plan

เพดานต่อรอบคงเดิม: 6 คำค้น Tavily basic, 3 Gemini requests, ไม่เกิน 12 แถวใหม่/แก้ไข ไม่ค้นทุกแหล่งใน registry ในวันเดียว

## แบ่งคำค้น

| ช่อง | เป้าหมาย |
| --- | --- |
| 1 | ตรวจงานเดิม 1 งานที่ปิดใกล้ที่สุดหรือยัง watch |
| 2 | ตรวจงานเดิมอีกงาน หรือประกาศขยายเวลา/ปิดรับของงานช่อง 1 |
| 3 | งานแข่งขัน/hackathon วิศวกรรมจากกลุ่ม source ที่เลือกวันนี้ |
| 4 | อีกสถาบันหรืออีกสาขาใน source กลุ่มวันนี้ |
| 5 | ค้นกว้างผ่าน CampHUB/site:ac.th เพื่อพบงานที่ไม่อยู่ในรายชื่อเดิม |
| 6 | เบาะแสจากช่อง 3–5 หรือหมวดเสริมตามวันของสัปดาห์ |

ถ้าไม่มีงานเดิม active/watch ให้ใช้ช่อง 1–2 ค้นงานใหม่ planner ต้องไม่ใช้ทั้งหกช่องค้นชื่อเดียวและไม่ใช้ปีเดิม hardcode

วิศวกรรมยังเป็นแกนหลักทุกวัน หมวดเสริมเป็นการขยาย ไม่ตัดงานมัธยมสาขาอื่นทิ้ง

## หมุนเวียนแหล่ง

เลือก 4 รายการจาก sources.json ตามจำนวนวันนับจาก epoch วันที่ไทยและเลื่อนทีละ 4 รายการ ไม่รีเซ็ตที่วันที่ 1 ของเดือน รอบจะครอบคลุม seed หลายกลุ่ม แต่ไม่รับรองว่าทุกแหล่งมีผลค้นหรือถูกเปิดอ่านครบ

Planner ใช้ชื่อ domain/keywords เพื่อคิด query ไม่จำเป็นต้องมีผลจากทุก source. แหล่งทั้งหมดใช้เป็น discovery; raw page จึงค่อยตรวจประกาศจริง

## ลำดับงานเดิม

ให้ตรวจใกล้ปิด/ไม่ทราบกำหนดก่อน พร้อมหมุนรายการที่เหลือเพื่อไม่ตรวจแต่งานเดิมที่ต้น array การได้ No changes ไม่ใช่สัญญาณให้ลบรายการหรือเปลี่ยน checked ทั้งหมด

## ช่องว่างที่ต้องรายงาน

- ค้นไม่พบ หรือได้หน้าคนละปี
- โพสต์ social/โปสเตอร์อ่านไม่ได้
- หน้าแบบฟอร์ม requires login
- มีแต่ข่าวประกาศผลหรือ recap
- คำค้นกว้างได้ข่าวรับเข้าปริญญาแทนค่าย
- URL ร่วมแต่ชื่อการแข่งขันคนละงาน
- วันปิดจาก aggregator ขัดกับเจ้าของงาน

เมื่อหลักฐานไม่ครบให้ watch/Unknown หรือไม่แก้ verified row; รอบต่อไปปรับคำค้นไปหาต้นทาง ไม่สร้างข้อมูลเพื่อให้ดูว่ามีการอัปเดต
